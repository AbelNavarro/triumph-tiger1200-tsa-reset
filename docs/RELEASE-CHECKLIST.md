# Release checklist

- [x] Establish separate Git history.
- [x] Summarize the confirmed repair and correct the superseded higher-level hypothesis.
- [x] Add MIT license for original content, citation metadata, safety and contribution policy.
- [ ] Obtain independent legal review of applicable licenses and scope of access material; coordinate any wider security concern with the manufacturer.
- [x] Extract the owner-tested level-1 repair workflow; omit higher-level and programming paths.
- [ ] Independently review final live implementation and transitive dependencies.
- [x] Exclude original raw captures, firmware and third-party code; use synthetic regression fixtures.
- [ ] Confirm latest CI run and allowlisted package.
- [ ] Rehearse on synthetic data. Validate the final supported workflow and package independently before distributing a live repair executable.
- [ ] Publish a GitHub release, then announce it with the verified compatibility scope.
- [ ] Optionally archive a reviewed release on Zenodo.

Never change the visibility of the original archive or copy its history into this repository.
